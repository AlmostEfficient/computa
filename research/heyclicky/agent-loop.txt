SETUP AND MODEL CALLS
The loop loads job configuration, MCP tool lists and first turn, builds model instructions/tool index through xi, and keeps conversation entries in M. Defaults: 120 model steps, 1800000ms wall budget, compactAt 160000. Individual model call maxMs defaults 600000, overridable by H1_MODEL_CALL_MAX_MS. A timed-out call's retry lowers effort through max→xhigh→high→medium→low (minimal/none preserved). Dc selects Claude adapter for model identifiers beginning claude-, otherwise Responses adapter. Event logging in Qe hardcodes provider openai/path /v1/responses even around this dispatcher; log labels alone cannot prove provider choice.

Each call drains steering notes and resolves image blobs into input. It collects output items, first-byte/output timings, token usage and tool names. Large result state above 800000 JSON characters stores output separately as a blob. Model errors emit a model_request record before propagating. The streaming onItem path Rr may start eligible box/web/MCP-read calls through ns before the full response completes. In this path ns has no direct cfg.earlyStart guard; creation sets earlyStart false, but that field alone is insufficient to conclude streaming tool execution is disabled. Plan events may be emitted early. Browser reads after a preceding browser write/script are held for ordered handling.

TURN BUDGET AND COMPLETION
Each model iteration checks the step cap and elapsed recorded model/tool time minus tracked waiting time. At 80% of step or time budget, it injects a wrap-up instruction. These are cooperative loop-boundary checks, not proof of a hard process wall-clock kill. No function calls normally ends the turn after any note closing check. A final message plus only successful async note/progress/plan calls can also end without another model round.

After tools and model output settle, finishOrTakeNotes atomically decides whether newly arrived steering requires another pass. Late messages on a completed turn are appended and processed; messages arriving as a failed/interrupted turn stops are mentioned as not applied. An info-only late update can preserve the earlier final text if it causes no new tool calls. Final events include message, step timeline, turn_end status, reason, model/workflow counts, search count and late-message count. The workflow then waits for the next turn. In the local Io adapter turn-N waits deliberately have no timeout despite the passed six-hour value; other runtimes may differ.

TOOL SCHEDULING
Calls are classified through Go. Read/box/web/search/note/progress/plan groups run through Oc using Promise.all; any eligible call already begun by ns is reused. MCP writes, routine writes and scripts run sequentially afterward. Their first workflow step has retries limit 0; a thrown non-interruption error triggers a separate resend step configured with two retries. This is not universal exactly-once execution. Caller idempotency keys use job and call ID; downstream support varies.

MCP PA retries selected network/HTTP failures: ordinary retryable errors allow four attempts total, HTTP 530 allows nine. Ordinary delays grow 1.5s per retry; 530 delay starts 2s and caps at 5s. mac_step gets 900000ms per call, other tools 180000ms. Returned workspace-change headers trigger pullFromMac. Tool result text is converted/capped and tunnel URLs rewritten. Composio result interpretation can turn a transport-successful call into a semantic failure. Read calls pass null idempotency key; writes receive their stable key.

Ask-user calls run after the other tool groups, emit a question with at most six choices, and wait for an answer with a nominal 30min timeout. Answers are recorded separately for future summarization. Waiting duration is subtracted from active elapsed time. The loop handles up to three mismatched answer events; a timeout breaks that wait sequence. Exact fallback text remains to be cataloged.

COMPACTION
Before compaction, old string tool outputs may be replaced with [Old tool result content cleared]. The loop preserves a recent approximate 40000-token tool-output allowance; pruning is applied only when it frees at least ~20000 estimated tokens. Estimates use characters/4 here, not a tokenizer. If still above threshold, jA compacts; context-overflow error permits one additional compaction-and-retry path.

For gpt- models, unless remoteCompaction false, it first POSTs to Responses /compact, with a 180s request timeout. Initial payload includes tools/cache key/reasoning; HTTP 400 causes a reduced retry without those fields. Success requires an output item of type compaction and filters developer messages from returned output. This is code behavior only, not proof the backend supports it. If remote compaction fails or is ineligible, it invokes model-generated summary/file-state compaction through Zp/pl, preserving side-effect and user-answer records. Full summary selection and splitting still need tracing.

Post-compaction reminder includes remaining time/steps, current plan, up to 40 persistent script-store keys and .clicky/memory.md content if present. Earlier injected compaction reminders and harness notes are removed from the material sent for compaction. Large compacted output can be stored by blob reference. Compaction notes can be disabled with cfg.compactionNote.

SCRIPT EXECUTION — SOURCE AND OFFLINE PROBE
jp (character range 352201–354792) constructs an AsyncFunction in the current JavaScript runtime. It supplies tools/text/progress/store/load/console and shadows process, require, Bun and globalThis with undefined. It does not create a separate process, worker or VM context. The script description's 'no files or network of its own' is not established by this mechanism: an exact-function Bun probe found fetch and setTimeout still visible while the four shadowed names were undefined. The probe only checked typeof; it performed no network request, filesystem action or escape attempt. Shipped runtime differences and broader isolation are not proven by this local probe.

Timeout is Promise.race against an interval that accumulates 1000ms ticks up to 180000 while no mac_step call is pending. It measures ticks rather than elapsed wall time, pauses during mac_step, and cannot interrupt synchronous code blocking the event loop. There is no cancellation passed to the generated function or pending tools on timeout. A synthetic fake tool remained pending when the accelerated watchdog returned 'ran past 180 s and was stopped', then completed after release. This confirms the error message overstates cancellation; it does not demonstrate real downstream side effects. Evidence: probes/harness-script.mjs, evidence/harness-script-probe.json, six assertions.

Tool proxy checks hasTool, counts calls, parses successful result text as JSON when possible, and throws for ok=false with text clipped to 2000 chars. It adds a rejection handler but returns the original promise; unawaited calls are not automatically joined. mac_step alone is in HI and contributes user-wait accounting. Script return value is printed on success, combined with text()/console output. At >40000 chars, output is clipped and saveOutput is asked to retain up to 20000000 chars. Collection checks the accumulated size before adding a whole string, so this is not a strict allocation ceiling for a single huge print.

store serializes JSON values and caps total serialized state at 100000 characters; undefined deletes a key. load returns a JSON clone. Probe confirmed mutating a loaded object does not mutate the stored object. Store changes are returned even when script execution fails. progress collapses whitespace, clips to 160 characters and forwards at most 20 nonempty messages per program.

CLASSIFICATION AND MCP SESSION NOTES

MCP classification FI applies device/browser allowlists and tool-name heuristics (still to catalog); classification is scheduling logic, not evidence of permission enforcement.

MCP session cache key is URL plus bearer token. Xo sends configured headers, protocol 2025-06-18, optional cached session, call ID and idempotency key. TOOL EXPOSURE AND CLASSIFICATION — VERIFIED PURE FUNCTIONS
Source ep/Mo/FI (~337300–340200) and xi (395322). ep sanitizes tool names to ASCII alphanumeric/underscore/hyphen and truncates to 64 characters. Custom connector names custom-<slug>-<six hex> get a normalized slug prefix; duplicate slugs include the hex ID. Existing names and reserved built-ins are skipped silently. First occurrence wins after sanitization/truncation, so distinct source names can collide. The index is a plain object and checks t[name] rather than own-property membership; inherited names such as constructor are skipped too. Eleven assertions in probes/harness-tools.mjs verify collisions, schema transformation and classification on synthetic definitions; evidence/harness-tools-probe.json retains results. No real tools executed.

Mo removes $schema, $id, examples, deprecated, readOnly, writeOnly and format metadata recursively; string format is appended to description instead. Named property/definition maps are processed by values so property names matching those metadata keys are retained. Function schemas are non-strict. These transformations can affect model guidance; they do not enforce validation or permissions.

FI treats device_list_folder/device_find_files/device_read_file/web_search on device as reads; other device tools as writes. Browser status/tabs/snapshot/extract/screenshot are reads, all other operations writes. Three Composio discovery/status tools are explicitly reads. Multi-execute is read only when nonempty and every slug passes the name heuristic. General read heuristic requires a token such as GET/LIST/READ/SEARCH/EXPORT/DOWNLOAD and rejects any write token such as DELETE/CREATE/POST/UPDATE. Unknown names default write. DOWNLOAD_FILE is classified read despite possible local writes; the classification is scheduling, not a side-effect guarantee.

xi requests parallel_tool_calls true, store false, max_output_tokens 128000 and reasoning effort default medium; the Claude adapter later caps output as documented separately. prompt_cache_key is limited to 64 characters. scriptMode only hides MCP definitions and direct search/fetch tools behind exec's generated description but retains other built-ins as configured; it is not a process sandbox. noProgressTool/noRoutinesTool suppress their definitions. Hosted web adds a native web_search tool. Note tools are included when a note path exists.

Tool listing Lp runs connectors in parallel. Optional connectors get two attempts, others six, with increasing one-second retry delay. Optional/runsWithout failures return empty tool lists; required connectors either use supplied fallbackTools or throw. No timeout at this aggregation layer beyond mp's per-request deadline. This behavior supports partial startup but is not evidence all configured tools are reachable.

LOCAL SUMMARY COMPACTION FOLLOW-UP
Qp selects older unpinned user/assistant history while aiming to retain ~20000 estimated tokens. If the cut falls within a turn it separately summarizes the turn prefix and can pin its original user-turn message. It skips pinned entries at the front. pl replaces the selected prefix with a user-role message containing <summary>, then preserved pinned material and the untouched suffix.

Fallback summary model Wp is hardcoded gpt-6-luna, effort low, store false, even when the main conversation uses a Claude model. It receives the summary task in the request instructions property, with flattened transcript in a user message. The general summary max_output_tokens is 13107; a split-turn prefix summary uses 8192. Incomplete status rejects the result and propagates through the workflow retry policy. This establishes another possible provider routing path, not an observed request.

Zp tells the summarizer to preserve goal/constraints/progress/decisions/next steps, exact paths/errors, deliverables, side effects and user answers. Existing summaries are updated; structured ledger tags are stripped from prior prose then regenerated. These prompts request fidelity but cannot guarantee model preservation. If no selected historical entries require summarizing, it retains the prior summary or 'No prior history.' Split-turn context is generated in a separate call and appended.

w$ builds read-files/modified-files from function_call names read/write/edit and their path arguments, unioned with previous ledger. It does not inspect call success, so failed writes can be listed as modified. Shell changes and file operations inside exec scripts are not discovered by this scanner. It preserves raw supplied paths rather than canonicalizing them. Modified paths are removed from the read-only list; both lists sorted. T$ appends those file lists plus recorded side-effect receipts and user answers verbatim in tags. These are call/history ledgers, not verified filesystem state.

The serialized transcript zp includes text and reasoning summaries, function-call arguments and tool outputs, but does not reproduce actual image pixels. Summary quality across image-dependent work therefore remains uncertain. Full algorithm and prompt source are retained in the extracted bundle; provider behavior cannot be established offline.
