CLOUD CONNECTION
Y2 selects an existing CLICKY_CLOUDFLARED path, /opt/homebrew/bin/cloudflared, or /usr/local/bin/cloudflared. L2 starts a loopback HTTP proxy and cloudflared tunnel --no-autoupdate with loopback metrics and target addresses. It extracts a trycloudflare.com URL from child output with a 60s deadline, polls metrics /ready with a 90s deadline and 3s request timeout, then optionally requires two consecutive successful backend probes within 120s measured from the readiness stage. h5 supplies that probe through worker.base/agent/harness/lab/h1/probe?url=<encoded-health-url>. The helper therefore involves backend requests even before a cloud tool call. None were made in this investigation.

A cached helper promise resets on startup rejection or cloudflared exit. Exit closes the proxy; process exit sends SIGTERM to cloudflared. Startup timeout paths do not visibly perform symmetric child/server cleanup in L2; whether external lifecycle handling cleans them remains unknown. Port selection briefly binds and releases a socket before actual bind. Per-job registration creates 24-byte base64url tokens and records both lexical and real workspace paths. Existing registration updates upstreams only; it retains token, workspace, cache and snapshot. No deregistration or cache eviction is visible in the extracted function.

PROXY CONTRACT
Unauthenticated /health returns ok. All /t/<key>/(mcp|ws) routes require the registered bearer using length check and timingSafeEqual. MCP requires POST. Unknown upstreams yield 404. Forwarding preserves accept, mcp-protocol-version and mcp-session-id, sets upstream bearer if present, uses 240s abort timeout, buffers the complete response, and returns content type and session ID. X_ registers upstream URL/token only: arbitrary headers from the original MCP definition are not propagated on this cloud path.

x-h1-idempotency-key caches an in-flight promise or completed response per registration, without comparing request body or upstream. A repeated key reuses that response with x-h1-deduped:1 and an empty workspace-change list. Failed promise or HTTP >=500 evicts it; other statuses remain. No size/TTL limit visible. This describes caching, not a demonstrated collision in real use.

Workspace PUT buffers a tar.gz, lists entries with /usr/bin/tar tzf (64MiB listing output limit), rejects any entry containing '..' or outside the expected workspace prefix, then extracts into the real workspace using strip-components. This is textual entry-name validation; link-target and tar implementation behavior remain unverified. GET /ws/file checks both lexical containment and realpath containment before reading. Body buffering has no explicit limit in these handlers, and request/header timeouts are disabled.

CHANGE REPORTING
xf recursively snapshots regular files by size and floored mtimeMs, skipping .git and node_modules directories. Symlinks are not traversed. P2 emits newly seen/changed metadata, updates the entire baseline, then returns only the first 40 entries. It does not report deletions and cannot detect changes with identical size and millisecond mtime. An exact-function synthetic probe confirmed 45 new files yield 40 reports, then zero on the next call although 5 were never reported; a deletion also yields zero. See probes/harness-workspace-delta.mjs and evidence/harness-workspace-delta-probe.json (five assertions). This is a limit of this header-based mechanism; end-of-turn archive transfer is a separate path and may recover files, so this alone does not prove permanent user data loss.

DEVICE TOOLS
E_ expands ~/ and resolves relative paths beneath home. qc rejects known private-path patterns in the supplied path and resolved realpath when available: .ssh, .gnupg, Library/Keychains, .aws, .config/gh, Clicky/CodexHome and .env variants. kc applies these checks before and after Bs path matching; M2 handles a destination through am. These checks are local to these functions, not an operating-system sandbox or a blanket policy over shell tools.

list_folder hides dot-prefixed entries and returns the first 200 unsorted entries with stat details. find_files invokes mdfind with 15s timeout and 4MiB output limit; errors are reduced to whatever stdout exists. It filters private-path patterns lexically, takes first 400 candidates, stats/sorts them newest first and returns 30. It is not globally newest-first over all matches, and does not apply qc realpath filtering per result.

read_file requires a regular file and allows at most 52428800 bytes, copies to workspace/inbox with a numbered unused name, and includes UTF-8 inline for files under 61440 bytes that contain no NUL. save_file checks source lexical workspace containment, resolves missing paths through Bs, and copies to a checked destination with collision numbering. Existing source symlinks are not explicitly realpath-contained in this function; behavior is distinct from /ws/file. Collision selection uses exists-then-copy without exclusive creation, so the 'never overwrites' description is not proven under concurrency. No real files were used to test these boundaries.

open accepts both HTTP and HTTPS despite the schema saying HTTPS, otherwise resolves/checks a local path, then uses /usr/bin/open. No open action performed. Device MCP handles initialize, ping, tools/list, tools/call; calls become MCP isError results on exceptions and unsupported methods get -32601. Notifications return no response.
