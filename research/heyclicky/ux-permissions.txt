AUTOMATION PROBE TIMEOUT AND LATE-RESULT HANDLING
Per-target helper FUN_101bbe6a0/101bbe744 runs a checked-continuation closure FUN_101bbf504 -> FUN_101bbedac. It dispatches the probe on a global user-initiated queue and separately schedules a deadline callback for now+1.5 seconds. Probe callback FUN_101bc17a4 -> FUN_101bbf79c supplies its computed status; timeout callback FUN_101bc1850 -> FUN_101bc02e0 supplies status 3 (unknown). Both pass through FUN_101bc16f4 -> FUN_101bbf510, whose lock-protected guard FUN_101689ca8 changes hasResolved from false to true only once. The winning callback resumes the continuation; the later one is ignored for result delivery. This does not cancel the underlying probe, and queue scheduling means 1.5 seconds is a requested deadline rather than a strict measured latency cap.
A timeout therefore permits an unknown row result, which the existing granted-only list filter omits. The timeout branch logs a diagnostic but constructs no user-facing timeout message. No automatic retry is scheduled in these per-probe callbacks; the surrounding view can later run a new inspection through its own lifecycle.
The probe FUN_101bbf854 calls AEDeterminePermissionToAutomateTarget with its final prompting argument zero. It maps result 0 to granted, -1743 to denied, -1744 to notDetermined, and other unhandled results to unknown. Result -600 has a special cache-dependent branch: membership in a bundle-ID set gives granted, otherwise notDetermined. Exact cache persistence and the platform meaning of that error are not yet established here, so this is not labeled as an installed-app existence test. Data encoding or descriptor creation failure returns unknown.
Every constructed automation row receives a Privacy_Automation settings URL via FUN_101bbe354/101bbe53c. These are permission inspection results and review links, not permission-request dialogs in this path.

AUTOMATION GRANT MEMORY PERSISTS ACROSS INSPECTIONS
The set used by the probe's -600 branch is persisted in standardUserDefaults under AgentPermissionInspector.observedGrantedAutomationTargets. Loader FUN_101bbea48 reads an array, conditionally casts it to Strings, falls back to an empty array if missing/invalid, and converts it to a Set. Writer FUN_101bbec7c converts the set back to an array and stores it under the same key. No expiry timestamp is part of these helpers.
On probe result 0, FUN_101bc0420 inserts the bundle ID if absent and persists the changed set. On -1743 or -1744, FUN_101bc0540 removes the bundle ID if present and persists the changed set. The -600 branch consults this remembered set, returning granted when present and notDetermined otherwise. Other unknown-result and timeout paths do not themselves clear the remembered set in the traced code. This explains how a granted row can be supported by a prior observation rather than a fresh successful check in that specific branch; it is not proof of current authorization in every case.
Clarification to the prior late-result note: the once-only guard protects continuation delivery, not all probe side effects. Grant-memory updates happen inside FUN_101bbf854 before its result reaches the guarded callback. A probe that completes after its timeout can therefore still update the persisted set even though its late row result is discarded. The current inspection stays unknown; a later inspection can use the updated memory. No immediate UI refresh is scheduled by these cache mutation helpers.
