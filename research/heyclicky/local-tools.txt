LOCAL TOOLS — HARNESS WRAPPER TRACE (PARTIAL)
Source evidence/harness-bundle.js ~439900–444200. Underlying bundled coding-tool implementations need deeper tracing. No shell commands or filesystem operations were executed through target tools.

The local dispatcher g2 exposes bash/read/write/edit through bundled factories; view_image is handled separately. Although broader library exports include grep/find/ls/powershell, this dispatcher does not automatically expose them. Bash sets exposeSessionEnvironment false and replaces child env with the prepared job env; this does not establish sandboxing. n_ creates the workspace directory, removes null-valued object properties recursively from tool arguments (null array elements survive), applies prepareArguments if supplied, and rejects edit calls without a nonempty edits array. It wraps tool exceptions as text/isError results.

Timeout normalization h2 treats finite positive values below 10000 as seconds and values >=10000 as milliseconds converted to seconds, then clamps to 1–1200s. Invalid/nonpositive values use the caller default (normally 300). This causes a discontinuity: 9999 becomes 1200s, but 10000 becomes 10s. Two exact-source pure-function assertions verified these boundaries plus null normalization; evidence/harness-local-limits-probe.json, probes/harness-local-limits.mjs.

Path helper Bs returns an existing exact path first. Otherwise it walks components from the root, preferring exact directory entries, then normalized matches (Unicode NFC, special spaces/apostrophes, whitespace collapse, lowercase), then wildcard matching if * or ? occurs. Wildcards omit dot-prefixed entries. Exactly one match advances; multiple matches throw with up to 12 candidates, and no match reports bounded suggestions. am resolves an existing destination or attempts matching only its parent, falling back on the original parent if matching fails. These helpers do not themselves restrict paths to the workspace; some callers add their own restrictions. Do not assume every library file tool uses Bs without tracing its factory.

view_image expands ~/, resolves relative paths against workspace, applies Bs, then checks png/jpg/jpeg/gif/webp extension. It attempts realpath and stats the file, rejects source >64MiB, reads and passes data to ll resizing, rejects dropped images, then rejects estimated decoded output >8MiB. It returns original path/byte count and normalized image data with scaling note. Output byte estimate is floor(base64.length*3/4), including padding overestimate. This wrapper has an explicit output limit distinct from ll's conditional conversion targets. No workspace containment or device-helper private-path filter appears in E2.

Remaining: shell process lifetime, kill/abort semantics and output-spill files; read offsets/image behavior; exact edit matching and mutation queue; write atomicity; bundled dependency versions/licenses and native permission enforcement.

SHELL PROCESS AND OUTPUT FOLLOW-UP
wd spawns a detached child after checking working-directory existence. It passes commands through the configured shell's argument or stdin transport, connects stdout and stderr to the same accumulator, registers the PID and attaches timeout/AbortSignal handling. Both cancellation and timeout invoke Ou, which sends SIGKILL to the process group, falling back to the individual PID. This differs from the MCP connector's SIGTERM behavior. These are static call paths; no shell process was launched to test descendant cleanup.

vE waits for exit plus drained stdout/stderr, or close. After exit it starts a 100ms idle timer, reset by more output; when it fires it destroys streams and resolves. This avoids waiting indefinitely for idle inherited pipes, but continuously arriving descendant output can extend the drain period. wd checks aborted/timed-out flags after waiting, converts signal termination into 128+signal when needed, and cleans PID/timer/listener registrations.

Td uses Mu to accumulate combined output; defaults are last 2000 lines or 51200 bytes, whichever is hit first. Mu incrementally decodes UTF-8, counts lines/bytes and keeps a rolling tail; it spills original byte chunks to a temporary file when needed and reports that path in truncation details. Snapshot truncation can retain a partial final line. Td finalizes output and closes the spill stream before reporting; nonzero exit, aborted, timeout and missing-exit-code results become errors containing retained output. The harness's n_ catches those errors into isError text. Underlying disk-spill naming/permissions/cleanup still need tracing.

The harness calls execute without the library's progress callback, so incremental library output callbacks are not automatically shown through this wrapper. Final output is still returned. No conclusion about native console streaming is warranted without tracing another path.

EDIT TRANSACTION TRACE
Vn acquires the shared per-path mutation queue, checks read/write access and abort state, reads the original UTF-8 file, separates BOM, detects/restores newline style, computes all replacements, then writes the resulting content in one writeFile call. Each edit matches the original content rather than earlier edits. All match/uniqueness/overlap checks precede the write. It checks abort again after writing, so an error caused by late cancellation does not prove no change occurred. No temp-and-rename or recheck against external modifications is visible in this default implementation.

Ld rejects empty oldText, missing matches, nonunique matches, overlapping matched ranges and no-op output. Despite exact-match wording, U0 falls back to Eo normalization: Unicode NFKC, trailing whitespace per line, smart quotes/dashes and special spaces. Uniqueness counting eF uses normalized strings even if an exact occurrence existed. If any replacement needs fuzzy matching, the normalized base is used to locate all replacements; AF preserves untouched original lines but rewrites affected line spans from normalized text. Therefore other typography/spacing on a touched line can normalize alongside the intended edit. Full fixture validation remains pending.

Mutation queue ii serializes operations by realpath for existing files, falling back to resolved lexical path for ENOENT/ENOTDIR. A global promise serializes queue-key setup; operations on different keys may run concurrently. Finally always releases the next waiter and removes its map entry when last. This coordinates participating operations within the same process, not other programs, separate processes or every alias of a nonexistent path. The write tool also participates in ii; note saves use a separate path and implementation.
