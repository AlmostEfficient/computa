CURRENT USER FLOW SUMMARY
- The tutorial teaches holding the voice shortcut, circling screen content and asking about it. The input path starts annotation watching only after its voice/drawing gates pass.
- Ink begins after sufficient cursor movement. Points and sustained pauses are retained as context. A stationary hold does not create a stroke.
- Ordinary release hides the marks, copies a description into pending voice context, then clears the original strokes in the traced preparation path.
- A voice hold shorter than 0.5 seconds can take a cancellation path that clears the marks.
- Escape during a recognized voice hold cancels it, clears marks and suppresses the following release, preventing that release from submitting the cancelled attempt.

This covers static lifecycle and control behavior, not a live usability test. Remaining material gaps include exact physical shortcut routing, drawing setting UI, fade rendering, cross-display coordinates, generated-drawing controls, accessibility, and successful answer delivery. Later evidence sections supersede earlier specific unresolved notes.

CURSOR MOVEMENT ACTIVATES A STROKE; PAUSES ARE RETAINED AS CONTEXT
The pointer subscription callback 102f48688 -> 102f43350 forwards sampled coordinates plus system uptime into 102f43464. That handler first requires isWatchingCursor. Before a stroke has started, it computes straight-line distance from holdStartCursorLocation and compares it with movementActivationThreshold (+0xa0). Only when that threshold is reached does it create the first stroke, using both the original hold position and current position as initial points, set hasStartedStrokeThisHold, initialize sample/dwell state, and invoke rendering/timer helpers. Thus merely holding the shortcut with an unmoved pointer does not create a stroke through this handler. Exact distance and display-unit interpretation remain unresolved.

After activation, the handler updates dwell tracking, conditionally appends sample coordinates/timestamps to the latest stroke, and requests a render update. Point-spacing predicate 102f4872c -> 102f44b20 remains to decode. Do not equate pointer sampling frequency with the number of retained stroke points.

Dwell helper 102f44918 keeps an anchor and start time. When the pointer moves beyond dwellRadius (+0xc0), it calls 102f43d34 to finalize the previous pause and starts a new anchor. Finalization requires a nonempty strokes array and elapsed time at least dwellMinimumDuration (+0xc8); it appends the anchor coordinates and elapsed duration to the latest stroke. The stop operation also calls this finalizer before clearing dwell state. Consequently pauses during an established stroke can be retained with the drawing; this does not yet establish visible pause markers or their downstream interpretation. A stationary hold before stroke activation does not enter this dwell-recording path.

Evidence: evidence/ux/annotation-pointer-processing.json, annotation-dwell-and-spacing.json and annotation-field-offsets.json. With a retained start timestamp and duration below 0.5 seconds, it cancels pendingKeyboardShortcutStartTask, invokes 1022d1a4c, resets the recording-start-chime flag, full-clears annotations, calls overlay cleanup, and returns before the ordinary release path. That helper first offers processing to 1018c0bc0 and otherwise invokes 1022d947c. The request completion and exact context payload remain to trace. ESCAPE DURING A VOICE HOLD — CANCEL AND SUPPRESS THE FOLLOWING RELEASE
Escape helper 1021e1784 checks whether pushToTalkPressStartTime is present. When present, it sets suppressPushToTalkReleaseAfterEscape, clears the start timestamp, cancels/clears pendingKeyboardShortcutStartTask, invokes the previously traced voice cancellation helper 1022d1a4c, resets the voice/presenter state and start-chime flag, full-clears screen annotations, and performs overlay cleanup. It returns handled. With no timestamp it returns unhandled. Earlier global Escape priorities still apply.

The input handler 101fe8df8's release-related branch reads suppressPushToTalkReleaseAfterEscape before ordinary release processing. When true, it clears the flag and returns immediately. This closes the accidental-submit question for this path: Escape cancels the held attempt, and the following release does not take the normal annotation-context/submission route. This does not retract already transmitted audio or undo actions completed before cancellation.

Evidence: evidence/ux/annotation-manager-integration.json (1021e1784 and 101fe8df8), voice-short-press-and-release.json and voice-short-press-cleanup.json. No keyboard input was performed.
